# LLVM backend stress corpus

Rocq programs that stress the runtime contract (`runtime_correct` in
`theories/CodegenLLVM/LambdaANF_to_LLVM_statement.v`) and the hard cases of
the LambdaANF -> LLVM correctness proof. See `CONTRACT.md` for how each
contract clause is tested.

Each `cNN_*.v` defines `Definition prog : T := ...`, needs only Stdlib, and
ends with `Example prog_expected : prog = <value> := ltac:(vm_compute;
reflexivity).`, so `rocq c cNN_*.v` checks the expected value (every file
compiles in under 2 s; with an 8 MiB stack Rocq overflows on c15, and the
plugin overflows on c04, so use `ulimit -s unlimited`).
The header comment has an `EXPECTED:` line with the
S-expression the driver should print. Format: an unboxed word `2n+1` prints
as `n` (nullary constructor ordinal, or a PrimInt63 shown unsigned), and a
boxed object prints as `(C<ordinal> field ...)`. Rocq tuples nest to the
left: `(a, b, c)` is `(C0 (C0 a b) c)`. `bool`: `true` = 1, `false` = 0 (the plugin's `Loader.v` registers
`CertiRocq Extract Inductives [ bool => "bool" [ 1 0 ] ]`, which also
renumbers the LambdaANF ordinals; `tests/llvm/mutual.v` and c00 confirm it).
PrimInt63 values print unsigned: `tests/llvm/llvm_main.c` decodes an
unboxed word with a logical shift.
`d7` is `D0..D6`, ordinals 0..6.

`c04`, `c07`, `c14` and `c15` are generated by `gen_corpus.py`.

## Running (for the harness in `tests/llvm/`)

`tests/llvm/run.sh -c -m checked -m asan` does all of the following (see
its header and `tests/llvm/RESULTS.md`). By hand:

1. Append the compile command to a copy of each file (or `Load` it), e.g.
   `From CertiRocq.Plugin Require Import CertiRocq.` followed by the LLVM
   compile command for `prog`. The `Example` is harmless; drop it if
   `vm_compute` time matters.
2. Link with `runtime/gc_stack_checked.c` **instead of** `gc_stack.c`.
   That file `#include`s `gc_stack.c`, so do not link both. Also link
   `prim_int63.c`, which c12 and c13 need. Example:
   `clang -O2 -I runtime prog.ll llvm_main.c runtime/gc_stack_checked.c runtime/prim_int63.c -lpthread`.
3. Run with `ulimit -s unlimited`. Tail calls (`Eapp`) are ordinary LLVM
   `call`s, and the escaping shadow-stack allocas stop LLVM from turning
   them into jumps. So c02 uses about 10^6 machine-stack frames and c03/c09
   about 5×10^4 to 10^5.
4. Set `CERTIROCQ_CHECK_MIN_GC=1` (or more) for every test except c00. At
   exit the runtime prints `certirocq-contract: OK gc_calls=N ...` on
   stderr. With fewer than the requested number of GCs it prints `FAIL` and
   exits with status 3. On a contract violation it prints
   `certirocq-contract: VIOLATION [<Rocq clause>] PRE|POST ...` and aborts
   (SIGABRT).
5. Expected-failure tests: c07 (`roots_ok` violation mentioning
   No_scan_tag), c13 (wrong result, crash, or a violation at a later GC) and
   c15 (`room` violation). They are correct Rocq programs within (c07, c15)
   or outside (c13) the theorem's hypotheses. When one of them passes, a
   runtime or emitter bug has been fixed.

`runtime-smoke/run_smoke.sh` is a standalone test of the checker against the
real collector, with no Rocq pipeline involved. It runs plain, under
ASan+UBSan, and with fault injection.
